# Server Storage Architecture

> **Hardware**: NVMe (`/dev/nvme0n1`) for hot/fast data + SATA HDD (`/dev/sda`) for bulk/warm data.
> **Filesystem**: BTRFS with LUKS encryption on both drives.
> **Goal**: Organized, multi-service, backup-ready, Proton-Drive-syncable, tiered by access speed.

---

## 1. Tiered Storage Model

| Tier | Drive | Mount | Role | Compression |
|------|-------|-------|------|-------------|
| **Hot** | NVMe | `/persist` | App databases, caches, thumbnails, metadata, working files | `zstd:1` |
| **Hot** | NVMe | `/data` | Active projects, hot-media cache, temporary working space | `zstd:1` |
| **Warm** | HDD | `/media` | Original media organized by content type (photos, videos, music, docs) | `lzo` |
| **Cold** | HDD | `/backup` | BTRFS snapshots, archives, local Proton Drive mirror | `lzo` |
| **Transient** | HDD | `/downloads` | Downloads, transient files, ingest staging area | `lzo` |

> **Rule of thumb**: If it is generated by an app (thumbnails, DB, transcoding temp) → NVMe.
> If it is an original file you captured or downloaded (photo, video, song) → HDD `/media`.

## 2. Directory Layout

### 2.1 NVMe — Hot Tier

```
/persist/
├── immich/                    # Already configured
│   ├── library/               # Thumbnails, processed video, faces, internal uploads
│   ├── postgres/              # Database
│   └── model-cache/           # ML models
├── jellyfin/                  # NEW — Jellyfin app data
│   ├── config/                # Server config, metadata, databases
│   └── cache/                 # Transcoding temp, artwork cache
├── proton-drive/              # NEW — Sync state, logs, local mirrors
│   └── sync-state/
└── backups/                   # NEW — Backup scripts state, snapshot manifests
    └── snapshot-timestamps/

/data/
├── cache/                     # Cross-app hot cache
│   └── jellyfin-transcode/    # Alternative transcoding location if /persist fills
├── hot-media/                 # Symlinks or bind-mounts to frequently accessed originals
└── working/                   # Active projects, temporary files
    └── ingest/                # Staging area before sorting into /media
```

### 2.2 HDD — Warm Tier (`/media`)

Organize by **content type**, not by application. This lets multiple apps (Immich, Jellyfin, Navidrome, etc.) point at the same canonical directory.

```
/media/
├── pictures/                  # Original photos
│   └── YYYY/                  # 2024/, 2025/, ...
│       └── MM/                # 01/, 02/, ... (optional)
│           └── event-name/     # Optional albums or events
├── videos/                    # Original videos
│   ├── home/                  # Personal / family videos (Immich + Jellyfin)
│   │   └── YYYY/
│   ├── movies/                # Feature films (Jellyfin)
│   ├── shows/                 # TV series (Jellyfin)
│   │   └── Series Name/
│   │       └── Season 01/
│   ├── clips/                 # Short clips, social media downloads
│   └── music-videos/          # Official music videos
├── music/                     # Music library (future: Navidrome, Jellyfin, MPD)
│   ├── artists/
│   ├── albums/
│   └── playlists/
├── documents/                 # PDFs, e-books, archived documents (future: Paperless-ngx)
│   ├── books/
│   ├── papers/
│   └── receipts/
├── ai/                        # Already configured — AI model weights
│   ├── llama-models/
│   └── llama-mmproj/
└── downloads/                 # Staging / transient (same as /downloads mount)
    └── sorted/                # Files already reviewed and moved to final location
```

### 2.3 HDD — Cold Tier (`/backup`)

```
/backup/
├── media-snapshots/           # BTRFS snapshots of /media
│   └── YYYY-MM-DD_HH-MM-SS/  # Named by timestamp
├── immich/                    # Immich library snapshot / export
├── system/                    # System-level backup configs, etc.
└── proton-drive-mirror/       # Local mirror of what is synced to Proton Drive
    └── (same hierarchy as selected sync sources)
```

## 4. Backup Strategy

### 4.1 Local Backup (BTRFS Snapshots)

A systemd timer runs daily to create read-only snapshots of `/media` into `/backup/media-snapshots/`.

**Snapshot retention policy**:
- Keep last **7 daily** snapshots
- Keep last **4 weekly** snapshots (Sunday)
- Keep last **3 monthly** snapshots (1st of month)
- Delete older snapshots automatically

**Implementation**:
```bash
# Create snapshot
btrfs subvolume snapshot -r /media /backup/media-snapshots/$(date +%Y-%m-%d_%H-%M-%S)

# Prune old snapshots (example: keep last 7 daily)
# Implemented as a Nix systemd service + timer
```

### 4.2 Proton Drive Off-Site Sync

A systemd timer runs weekly to sync selected directories to Proton Drive.

**Workflow**:
1. `proton-drive sync /media/pictures /Backups/Server/Pictures`
2. `proton-drive sync /media/documents /Backups/Server/Documents`
3. For large snapshots, use `btrfs send` + compress before upload.

### 4.3 Restore Procedure

```bash
# Restore from local snapshot
btrfs subvolume delete /media   # if corrupted
btrfs subvolume snapshot /backup/media-snapshots/YYYY-MM-DD_HH-MM-SS /media

# Restore from Proton Drive
proton-drive sync /Backups/Server/Pictures /media/pictures --download
```

## 5. Ingest & Organization Workflow

New files should follow a simple workflow:

```
1. Download / capture / receive →  /downloads/  (or /data/working/ingest/)
2. Review, tag, rename         →  manual step
3. Sort into canonical path    →  /media/<type>/YYYY/MM/<event>/
4. Trigger service scan        →  Immich / Jellyfin detect new files
5. Nightly snapshot            →  /backup/media-snapshots/
6. Weekly cloud sync           →  Proton Drive
```

To realize this design, the following modules need changes or additions:

| Module | Change |
|--------|--------|
| `hosts/server/disko.nix` | **No change needed** — existing subvolumes (`@data`, `@persist`, `@media`, `@backup`, `@downloads`) already map to the tiers. |

| `modules/server/proton-drive.nix` | **NEW timer unit** — Weekly systemd timer to sync selected `/media` paths to Proton Drive. Add sync script wrapper. |
| `modules/server/default.nix` | Import new modules (`jellyfin.nix`, `media-backup.nix`). |

## 7. Summary Rules

1. **Content type > Application** — `/media/pictures` serves Immich, Jellyfin, and any future app.
2. **Originals on HDD, derived data on NVMe** — App caches, DBs, thumbnails never touch `/media`.
3. **Read-only from containers** — All container mounts of `/media/*` use `:ro` unless write is explicitly required.
4. **Snapshot before sync** — Always snapshot `/media` before Proton Drive upload so the cloud state matches a known point-in-time.
5. **Date-based organization** — Use `YYYY/MM/` for time-series media (pictures, home videos) for easy browsing and efficient snapshots.
